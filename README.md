# 사장님도 퇴근합니다

자영업 사장님들이 가게 운영 경험과 고민을 나누는 커뮤니티 프로젝트입니다.

## 프로젝트 진행 현황

- **완료:** 1~12단계
- **다음 단계:** 13단계 — 알림
- **12단계 완료:** 운영센터, 이용규칙·개인정보처리방침·이용약관, 공지/이벤트 DB·RLS, 관리자 작성·수정·삭제·공개관리
- **댓글 익명 기능:** 일반회원과 관리자 모두 게시글 상세 댓글 작성 시 `익명으로 작성하기`를 선택할 수 있으며 `comments.is_anonymous`에 저장됩니다.
- **작업 원칙:** 실제 코드와 Supabase 동작을 확인한 뒤 한 단계씩 진행합니다. 기존 기능과 디자인을 불필요하게 깨뜨리지 않고, 구현 후 실제 사용자 테스트를 거쳐 완료 처리합니다.

## 실행

```bat
cd D:\sajangnim-community
git pull origin main
py -m http.server 3000
```

브라우저: **http://localhost:3000**

수정 후에는 `git pull origin main` 후 브라우저에서 `Ctrl + F5`로 강력 새로고침합니다.

> Git 충돌이 발생하면 임의로 `git reset --hard`를 실행하지 말고 `git status`와 오류 메시지를 먼저 확인합니다.

## 현재 주요 기능

### 회원/마이페이지
- 이메일, Google, Kakao 로그인
- 프로필 닉네임·업종·소개 수정
- 내가 작성한 게시글: **페이지당 5개**
- 내가 작성한 댓글: **페이지당 5개**
- 각 목록에 이전/다음 페이지 이동 및 전체 개수 표시

### 게시글/댓글 수정 UX
- 본인 게시글 상세에서 `✏️ 수정 / 🗑️ 삭제`
- 게시글 수정 시 제목/본문을 상세창 안에서 바로 수정
- 댓글 수정 시 해당 댓글 자리에서 바로 수정
- `저장 / 취소` 방식이며 기존 `prompt()` 수정 팝업 제거
- 마이페이지의 수정 버튼도 상세 인라인 수정으로 연결
- 댓글 작성 시 `익명으로 작성하기` 지원
- 관리자 계정도 게시글 상세에서 동일하게 익명 댓글 작성 가능

### 관리자 시스템
- 신고/게시글/댓글 목록: **페이지당 20건**
- 회원 목록: **페이지당 20명**
- 역할/상태/업종 필터 및 회원 검색
- 회원 선택 → 회원정보 최근 게시글/댓글 각각 **5개씩 독립 페이지네이션**
- 서버 전체 통합검색은 분류별 최대 100건 검색 유지
- 신고 대상 원문 확인 및 숨김·삭제·복구
- 관리자도 일반 댓글 작성창의 `익명으로 작성하기` 사용 가능
- 공지 관리
- 이벤트 관리

## 댓글 익명 처리 — 완료

- 게시글 상세 댓글 작성창에 `익명으로 작성하기` 체크박스 제공
- 기본값은 익명 작성
- 일반회원과 관리자 모두 동일한 댓글 작성 흐름 사용
- 체크 상태는 `comments.is_anonymous`에 저장
- 익명 댓글은 목록에서 `익명 사장님`으로 표시
- 관리자 계정이라고 해서 익명 설정을 강제로 해제하지 않음

## 11단계 관리자 보안 — 완료

- `profiles/posts/comments/reports/reactions` 핵심 5개 테이블 RLS 활성 확인
- `posts/profiles/reactions` 최소 권한 적용
- 일반회원 게시글 작성/본인 수정/본인 삭제만 허용
- 프로필은 본인 닉네임·업종·소개 수정만 허용
- 브라우저에서 `profiles.role/status` 직접 변경 차단
- 공감 등록/취소는 로그인 회원 본인만 허용
- 신고 INSERT는 본인 `reporter_id + PENDING`으로 제한
- 관리자 함수 `SECURITY DEFINER + search_path=""` 확인
- 일반회원 `role=ADMIN` 직접 변경 시도 → HTTP 403 확인
- 일반회원 `admin_page_members` 직접 호출 시도 → HTTP 403 확인
- `config.js`에는 브라우저용 publishable 키만 사용하고 `service_role` 키는 두지 않음

## 12단계 공지·운영 페이지 — 완료

### 운영센터/문서

`operating-pages.js`

- 메인 화면에 `📢 공지 · 운영센터`
- 공지사항/이벤트 영역
- 이용규칙 모달
- 개인정보처리방침 **운영 초안** 모달
- 이용약관 **운영 초안** 모달
- 사이트 하단 푸터
- 모바일 레이아웃 대응

### 공지/이벤트 DB 및 관리자 기능

`supabase-step12-operating-content.sql`

- `notices` 테이블 생성
- `events` 테이블 생성
- 두 테이블 모두 RLS 활성
- 공개 사용자는 `PUBLISHED` 항목만 조회
- ACTIVE 관리자/운영자는 전체 조회·등록·수정·삭제 가능
- 초기 공지 2건 DB 등록

`operating-db-sync.js`

- 메인 운영센터의 공지/이벤트를 Supabase 데이터와 연결
- DB 조회 실패 시 기존 정적 운영센터를 유지하는 폴백 적용

`admin-operating-content.js`

- 관리자 대시보드 `📢 공지 관리`
- 관리자 대시보드 `🎉 이벤트 관리`
- 공지/이벤트 작성·수정·삭제
- 공개/숨김 상태 관리
- 공지 상단 고정 관리

### 실제 검증 완료

- `notices` RLS `true`
- `events` RLS `true`
- 공개 SELECT 정책 확인
- 관리자 SELECT/INSERT/UPDATE/DELETE 정책 확인
- 초기 공지 2건 확인
- 관리자 `공지 관리 / 이벤트 관리` 실제 동작 확인
- 기존 로그인/게시글/댓글/마이페이지/관리자 기능 정상 확인

### 중요

현재 개인정보처리방침과 이용약관은 **정식 법률 확정본이 아니라 실제 서비스 구조에 맞춘 운영 초안**입니다. 정식 공개 전 다음 정보가 확정되어야 합니다.

- 운영자/사업자 표시 정보
- 문의 연락처 또는 이메일
- 실제 회원탈퇴 및 게시물 보존 정책
- 개인정보 보유기간
- Supabase 및 OAuth 관련 처리/위탁/국외 이전 여부와 실제 설정

17단계 최종 보안·개인정보 점검에서 현재 법령과 실제 운영 설정을 다시 대조합니다.

## 13단계 예정 — 알림

다음 단계에서는 먼저 알림 데이터 모델과 RLS를 설계한 뒤 UI를 연결합니다.

예정 범위:
- 내 게시글에 새 댓글 알림
- 내 게시글에 공감 알림
- 읽음/안읽음 상태
- 알림 목록
- 읽지 않은 알림 개수 배지
- 알림 클릭 시 관련 게시글/댓글로 이동
- 본인이 자기 글에 댓글/공감한 경우 알림 생성 제외
- 중복 알림 정책 검토
