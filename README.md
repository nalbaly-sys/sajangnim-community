# 사장님도 퇴근합니다

자영업 사장님들이 가게 운영 경험과 고민을 나누는 커뮤니티 프로젝트입니다.

## 프로젝트 진행 현황

- **완료:** 1~10단계
- **현재 진행:** 11단계 — 관리자 보안 1차 하드닝 및 RLS 점검
- **작업 원칙:** 실제 코드와 Supabase 동작을 확인한 뒤 한 단계씩 진행합니다. 기존 기능과 디자인을 불필요하게 깨뜨리지 않고, 구현 후 실제 사용자 테스트를 거쳐 완료 처리합니다.

## 4. 관리자 전용 Supabase RPC

기존 함수:
- `admin_get_report_target`
- `admin_set_report_target_status`
- `admin_list_comments`
- `admin_list_post_comments`

페이지네이션/검색 함수:
- `admin_page_reports`
- `admin_page_posts`
- `admin_page_comments`
- `admin_unified_search`
- `admin_page_members`

관리자용 신규 RPC는 `SECURITY DEFINER`를 사용하고 함수 내부에서 다음 조건을 검사합니다.
- `auth.uid()`와 일치하는 프로필
- `role IN ('ADMIN','MODERATOR')`
- `status = 'ACTIVE'`

## 5. 11단계 관리자 보안

### 1차 하드닝 SQL

저장소의 `supabase-step11-security-hardening.sql`을 Supabase SQL Editor에서 전체 실행합니다.

이 SQL은 다음 작업을 수행합니다.

1. `public.is_active_admin()` 공통 관리자 판별 함수 생성
2. `profiles.role` / `profiles.status` 보호 트리거 생성
3. 일반 회원이 자기 프로필 업데이트 요청으로 관리자 역할 또는 상태를 바꾸려는 시도를 DB에서 차단
4. 주요 관리자 RPC의 `PUBLIC` 실행 권한 회수
5. `authenticated` 역할에만 관리자 RPC 실행 권한 부여
6. `profiles`, `posts`, `comments`, `reports`, `reactions` RLS 활성 여부 출력
7. 현재 RLS 정책의 `qual / with_check` 조건 출력
8. 관리자 함수의 `SECURITY DEFINER`, `search_path`, ACL 상태 출력

### 11단계 완료 조건

아래 항목을 실제 테스트해야 완료 처리합니다.

- [ ] 중요 테이블 RLS가 모두 활성화되어 있음
- [ ] 일반 회원이 `profiles.role`을 `ADMIN` 또는 `MODERATOR`로 바꿀 수 없음
- [ ] 일반 회원이 `profiles.status`를 임의 변경할 수 없음
- [ ] 일반 회원이 관리자 전용 RPC를 직접 호출하면 권한 오류 발생
- [ ] 관리자 계정은 관리자 RPC를 정상 호출 가능
- [ ] 일반 회원이 다른 회원의 프로필을 임의 수정할 수 없음
- [ ] 일반 회원이 다른 사람의 게시글/댓글 상태를 `HIDDEN` 또는 `DELETED`로 바꿀 수 없음
- [ ] 신고 상태 변경도 관리자 권한 없이 수행할 수 없음
- [ ] 관리자 SECURITY DEFINER 함수에 고정 `search_path`가 설정되어 있음
- [ ] 관리자 RPC의 `PUBLIC` 실행 권한이 없음

## 6. 보안 원칙

- Supabase anon/publishable 키는 브라우저용 공개 키입니다.
- `service_role` 키, OAuth client secret, 비밀번호 등 비밀정보를 GitHub나 `config.js`에 저장하지 않습니다.
- 관리자 메뉴가 화면에 안 보이는 것은 보안이 아닙니다. 실제 권한은 DB에서 차단해야 합니다.
- RLS 오류가 발생해도 RLS를 끄거나 전체 공개 정책을 추가하지 않습니다.
- `SECURITY DEFINER` 함수는 내부 관리자 검증과 고정 `search_path`가 필수입니다.
- 일반 회원이 자기 프로필을 수정할 수 있어도 `role/status`는 DB 레벨에서 보호합니다.
