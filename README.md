# 사장님도 퇴근합니다

자영업 사장님들이 가게 운영 경험과 고민을 나누는 커뮤니티 프로젝트입니다.

## 프로젝트 진행 현황

- **완료:** 1~10단계
- **다음 단계:** 11단계 — 관리자 보안
- **작업 원칙:** 실제 코드와 Supabase 동작을 확인한 뒤 한 단계씩 진행합니다. 기존 기능과 디자인을 불필요하게 깨뜨리지 않고, 구현 후 실제 사용자 테스트를 거쳐 완료 처리합니다.

## 1. 준비물

- Windows PC
- Git 설치
- Python 설치 (`py` 명령어 사용 가능)
- GitHub 저장소 접근 권한
- Supabase 프로젝트 접근 권한

## 2. 처음 실행하기

```bat
cd D:\sajangnim-community
git pull origin main
py -m http.server 3000
```

브라우저에서 아래 주소를 엽니다.

**http://localhost:3000**

서버 종료는 실행 중인 CMD에서 `Ctrl + C`를 누릅니다.

## 5. 관리자 시스템 — 10단계 완료

관리자 화면은 `profiles.role`이 `ADMIN` 또는 `MODERATOR`이고 `profiles.status`가 `ACTIVE`인 사용자에게 표시됩니다.

현재 구현된 관리자 기능:

- 관리자 대시보드
- 신고 관리
- 게시글 관리
- 댓글 관리
- 회원 목록
- 회원 활동 상세
- 관리자 통합검색
- 신고 상태 한글화 및 색상 배지
- 게시글/댓글 상태 한글화 및 색상 배지
- 회원 역할/상태 한글화
- 신고 대상 게시글/댓글 원문 확인
- 관리자 게시글 상세에서 즉시 숨김·삭제·복구
- 관리자 댓글 상세에서 즉시 숨김·삭제·복구
- 숨김/삭제 댓글 관리자 전용 조회
- 통합검색에서 신고·게시글·댓글·회원 검색
- 검색어 빨간색 강조
- 검색 결과에서 원문 위치로 바로 이동

### 관리자 화면 한글 상태

| 원본 값 | 관리자 화면 표시 |
|---|---|
| `ACTIVE` | 공개 / 정상 |
| `HIDDEN` | 숨김 |
| `DELETED` | 삭제 |
| `PENDING` | 접수중 |

## 6. 관리자 전용 Supabase RPC

현재 관리자 기능에서 사용하는 주요 함수:

- `admin_get_report_target`
  - 숨김/삭제된 신고 대상 게시글·댓글을 관리자 권한으로 조회
- `admin_set_report_target_status`
  - 게시글·댓글 상태를 `ACTIVE / HIDDEN / DELETED`로 변경
- `admin_list_comments`
  - 관리자 댓글관리에서 공개·숨김·삭제 댓글을 모두 조회
- `admin_list_post_comments`
  - 관리자 게시글 상세에서 해당 게시글의 공개·숨김·삭제 댓글을 모두 조회

이 함수들은 관리자 UI 편의를 위한 공개 우회 기능이 아니라, 관리자 권한 확인이 포함된 `SECURITY DEFINER` 방식으로 구성했습니다.

## 7. 보안 주의사항

- Supabase anon/publishable 키는 브라우저용 공개 키입니다.
- 실제 데이터 보호는 반드시 RLS와 서버 측 권한 검증으로 처리해야 합니다.
- `service_role` 키, OAuth client secret, 비밀번호 등 비밀정보를 GitHub나 `config.js`에 저장하면 안 됩니다.
- 관리자 메뉴가 화면에 보이지 않는 것만으로 보안이 확보되는 것은 아닙니다.
- 관리자용 RPC는 반드시 내부에서 관리자 역할과 계정 상태를 검증해야 합니다.
- RLS 오류가 발생해도 보안을 위해 RLS를 끄거나 전체 공개 정책을 추가하지 않습니다.

## 8. 다음 단계 — 11단계 관리자 보안

다음 작업에서는 기능 추가보다 **현재 관리자 기능의 권한 경계 검증**을 우선합니다.

주요 점검 대상:

1. `profiles.role / status`를 일반 사용자가 수정할 수 없는지 확인
2. 관리자 전용 RPC마다 `auth.uid()` 기반 관리자 검증 확인
3. 일반 사용자가 관리자 RPC를 직접 호출했을 때 차단되는지 테스트
4. `posts`, `comments`, `reports`, `profiles` RLS 정책 점검
5. 브라우저 직접 REST 요청으로 관리자 동작을 우회할 수 없는지 확인
6. 관리자 상태 변경 기록 또는 감사 로그 필요 여부 검토
7. 회원 경고 기능을 추가할 경우 별도 경고 이력 테이블과 관리자 전용 처리 방식 설계

## 11. 관리자 계정 역할과 상태

| 컬럼 | 값 | 의미 |
|---|---|---|
| `role` | `ADMIN` | 최고 관리자 |
| `role` | `MODERATOR` | 운영 관리자 |
| `role` | `USER` | 일반 회원 |
| `status` | `ACTIVE` | 정상 계정 |

관리자 메뉴 조건:

- `role IN ('ADMIN', 'MODERATOR')`
- `status = 'ACTIVE'`

브라우저 콘솔이나 공개 UI에서 역할을 변경하는 기능을 만들지 않습니다.
